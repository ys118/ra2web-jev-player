**Confirmed key mechanics** (hard conclusions written into the docs; all of them can be re-checked in this directory):
- Warhead × armor multipliers (`Verses=` in `rules.ini`): tank cannon 25% vs. infantry, Prism 200% vs. buildings / 50% vs. heavy armor, Mirage 100% vs. heavy armor / 20-30% vs. buildings, Flak Cannon 150% vs. air.
- Flak Cannon / Patriot **hit air only**: `LandTargeting=1`; the engine enum in `app.js` is `LandOk=0 / LandNotOk=1 / LandSecondary=2`.
- Power: Tesla Reactor +150 / Allied Power Plant +200; Ore Refinery -50, Barracks -10, War Factory -25, Radar -50, Coil -75, Flak Cannon -50, **Sentry Gun 0**.
- Low-power penalty: production speed cap ×0.5 (worst case ×0.1); defensive towers with `Powered=yes` go offline.
- Multi-factory speedup `MultipleFactory=0.5`; sell refund 50%; official ratio `HarvestersPerRefinery=2`.
- Ore: gold ore 25 credits/cell, gem ore 50 credits/cell; miner capacity 45 (Soviet) / 25 (Allied); Ore Purifier +25%; Spy steals 50% of cash.
- Veterancy: `VeteranROF=0.6`, speed/sight ×1.2, armor ×1.5, and the threshold is proportional to cost (`VeteranRatio=3`).

## 2. Reproduction / refresh pipeline (copy as-is)

> Prerequisite: this machine can only reach domestic (mainland-China) sites. Python always goes through the project's uv environment: `uv sync --all-groups` at the repo root,
> after which `uv run python ...` works from any directory (the research dependency group ships requests);
> any system Python 3.11+ works as a fallback if you install the dependencies by hand.
> After a game version change (visible on the home page, e.g. v0.87.0-r79e73e7), refresh the whole thing with this pipeline.

```bash
cd <repo>/references/research

# 1) Fetch client data (rules.ini is the key file; ra2.csf holds the Chinese names; app.js is for looking up engine semantics)
curl -s -A "Mozilla/5.0" -o rules.ini https://game.gongheguozhihui.com/res/overlay/rules.ini
curl -s -A "Mozilla/5.0" -o ra2.csf   https://game.gongheguozhihui.com/res/overlay/ra2.csf
#    app.js / art.ini / version.json / config.json live on the same site (exact paths: see the home page <script src>)

# 2) Chinese name table
uv run python decode_csf.py                 # ra2.csf -> csf_decoded.json (4523 entries)
uv run python decode_csf.py --compare       # compare against the existing file (self-check)

# 3) Numeric extraction tables
uv run python extract_rules.py && uv run python extract2.py   # -> rules_extract.md / rules_extract2.md

# 4) Machine-readable table (writes ../knowledge/RA2-UNITS.json; a regeneration must match the archive byte for byte)
uv run python gen_json.py

# 5) Reconciliation check (56 items: units/weapons/buildings/warhead multipliers/global parameters)
uv run python verify.py

# 6) Tactics crawling (optional; the media site's structure may change)
uv run python web.py search "<Chinese query: Red Alert 2 Soviet tactics>"   # search (Bing RSS channel)
uv run python fetch_pages.py                                                # fetch the articles on the list -> pages/
```

## 3. Pitfalls unique to this directory (hard-won)

1. **Passing Chinese arguments through Bash gets them transcoded to GBK** (Git Bash → curl/Bing receive mojibake and return junk hits such as "red culture" pages).
   → Always put Chinese text into a `.py` script (written as UTF-8 with an editor / the Write tool) and run that; pass only ASCII on the command line.
2. **The outside internet is unreachable** (google/fandom/github/wiki time out) → use the `cn.bing.com` **`format=rss`** channel; it is the most reliable.
   `baidu.com` is reachable; `sogou` 302s; `baike.baidu.com` returns 403 to scripts.
3. **Bing RSS degrades long queries**: an overly long query comes back with generic results → use a **short query + a `site:` prefix** (e.g. `site:uc129.com <Chinese: tactics>`).
4. **Three CSF decoding pitfalls** (`decode_csf.py` already handles them):
   - the value area is UTF-16LE, with **every code unit XORed by 0xFFFF** (`\xff\xa0` → U+5F00);
   - `LBL` records carry one int32 more than the standard (value count = 1);
   - records with the `W` flag (`WRTS`) are followed, after the value, by `int32 length + ASCII` (e.g. `VOX:CEVA001` → the `ceva001` audio name).
   The old decoder missed point 3 → 1204 voice entries came out empty; the current version covers 4523/4523.
5. **`rules.ini` has no `BuildTime` field**: build time accumulates from cost (`app.js`: `cost/buildSpeed*multi, 54`), so only relative values can be given.
6. **`app.js` contains a separate "rush mode" parameter table** (`HTNK:{health:1080,maxSpeed:221,...}`), **do not mix it with rules.ini**.
7. Facts about `werhd.help()` / the console API are authoritative in `../werhd/player-console-api.md` (not repeated in this directory).

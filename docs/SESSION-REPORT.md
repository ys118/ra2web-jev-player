## 一、架构：快照 → jev 判定 → 执行

```
┌────────────── 每 ~2.5 秒一个 tick（真实时间）──────────────┐
│ ① 状态采集  单次 JS eval 拉全量 JSON：                      │
│    资金/电力/双方单位(位置·血量·状态)/生产队列/可造列表      │
│ ② 确定性规则层（不花 jev 钱、零延迟）                       │
│    部署基地车(节流45s) → 就绪建筑落位(螺旋找位) →           │
│    开局建造序列 → 采矿车补员 → 坦克资金保底 → 防空保险      │
│ ③ jev 语义决策（tsj 单次批量 5 问，~0.7-1s）                │
│    q_build 下一建筑 / q_inf 步兵 / q_veh 载具 /             │
│    q_stance 发展·防守·进攻 / q_threat 基地受威胁概率        │
│ ④ 执行  werhd.order/produce/place 直接下单                 │
└──────────────────────────────────────────────────────────┘
```

**决策分工原则**（遵循 TypeSafe 最佳实践「能用代码算的绝不给模型」）：
- 确定性代码管**机制**：部署、落位、建造序列、经济保底、指令节流。
- **jev 管 semantic 拍板**：攻防态势转换、威胁评估、兵种搭配、开局结束后的建筑优先级。
- jev 答案带 confidence 闸门（<0.45 不切换态势），一次 tsj 调用批量问 5 问（比逐问省 10 倍延迟与费用）。

## 二、核心资产：游戏自带的 `window.werhd` 控制台 API

 这是本项目最大的发现——游戏官方暴露了玩家战场控制台（文档：`werhd.help()`）：

| 类别 | API |
|---|---|
| 查询 | `me() players() units('self'/'hostile') unit(id) production.queues() production.available(0-3) map.size() canPlace(name,x,y) camera.centerAt(x,y)` |
| 指令 | `move attack attackMove stop gather deploy(ids) produce(name,qty) cancel place(name,x,y) sell repair select(ids) resign()` |
| 枚举 | `OrderType QueueType QueueStatus BuildCat ObjectType QueueStatus` |

- 队列类型：0建筑 / 1防御 / 2步兵 / 3载具 / 4飞机 / 5船；状态：0空闲 / 1生产 / 2暂停 / **3就绪待放置**。
- 指令走与鼠标相同的**锁步队列，异步生效**（本文多个坑皆源于此）。
- `units('hostile')` 会混入 `@@NEUTRAL@@` 平民单位/建筑 —— 必须按 `u.owner.indexOf('@@AI')===0` 过滤才是真敌人。

## 四、引擎级大坑（血泪换来的协议细节）

1. **`move()/attack()/attackMove()` 封装在本版本失效**——单位接令（idle=false）但永不移动。
   ✅ 解法：用原始原语 `werhd.order(ids, 4 /*AttackMove*/, x, y)`，实测 velocity 立即变化。
2. **大 id 数组指令被静默丢弃**——34 辆坦克一个 order 无效果。
   ✅ 解法：按 **≤5 辆/批** 分发。实测 5 辆小队正常行军。
3. **锁步队列 + 高频重发 = 单位瘫痪**——每 tick 重发指令，单位刚要起步就被新命令重置，永远 idle。
   ✅ 解法：同一目标 12 秒内不重发；目标变更才发新令。
4. **部署基地车的横跳**——`基地重新部署`选项开启时建造厂也有 canDeploy；且 deploy 异步，反复下令=车↔厂横跳。
   ✅ 解法：只对 `type===7`（载具形态）+ 45 秒节流。
5. **`units('hostile')` 含平民**——一个 2000 血平民小屋曾吸引全部坦克围殴半天。
   ✅ 解法：owner 前缀 `@@AI` 过滤（平民是 `@@NEUTRAL@@`）。
6. **`production.available()` 返回形态不定**（字符串数组或对象数组）。
   ✅ 解法：采集层统一 `.map(x=>x.name||x)` 归一化。
7. **游戏引擎会过载冻结**——21 座精炼厂+15 采矿车+40 坦克的局，模拟 tick 停摆、渲染线程挂起（截图 10060 超时但 eval 仍响应）。
   ✅ 解法：精炼厂硬上限 2（jev 选项里剔除）、坦克数量管理、每 tick 只发 12 秒节流内的指令。

## 六点六、快响应改造 + 第 13-17 局（2026-09-21 中午）

用户反馈"敌人打基地时旁边的兵没反应"后的专项改造：

**根因与修复**
1. **防守用错指令语义**：此前防守/集结用 `Move(0)`——红警里 Move 是"走路不还手"，兵走到家就站桩挨打。改为**攻击移动 AttackMove(4)**，路上遇敌即交火。
2. **感知太钝**：原来只靠"敌人进入 18 格"与 jev 每 tick 威胁投票。新增 **sense_events() 事件差分层**：建筑掉血（最早信号）/单位损失/敌逼近/新敌出现 → MEM.events 事件流 + alarm。实战验证：t=602 "ALARM 敌军逼近 → 38 units counter"（一 tick 内全军反击）。
3. **危机先打后想**：alarm 触发时跳过 jev 调用（省 ~1s），确定性反击优先，下个平静 tick 再交给 jev。
4. **循环提速**：sleep 1.5→0.7，状态拉取实测 0.04s，整 tick 约 1.6s（原 ~3.5s）。

**jev 上下文增强（用户要求"详细背景"）**
- state 新增：`最近事件`流（新→旧最多5条：受击明细/损失/敌逼近距离与编成）、`兵力价值对比`（我方≈X vs 视野敌军≈Y 按造价折算）、敌方编成按护甲归类附克制建议、faction 阵营信息（含法国巨炮提示）。

**本轮新挖出的引擎/工程坑（全部已修）**
1. **`werhd.tick()` 已被引擎移除**（返回 undefined）——bot 的"状态无 tick"守卫把正常对局误判为无效，每 3 秒空转 10 分钟后自杀。这就是 10:30-11:25 所有"bot 卡死"的真相（faulthandler 栈定位）。已改用 `time()` 做停摆信号。
2. **cmd.exe shim + 继承 stdin = 永久挂死**：Popen 未设 stdin=DEVNULL 时，cmd 解析带括号的 `eval(atob(...))` 参数会等 stdin 而永不返回。已修。
3. **截图/快照挂起会传染**：无头模式下合成器停帧时，等待帧的操作无限挂起→rAF 停摆→模拟冻结（第 10 局元凶）。已改有头模式并给所有子进程加超时+taskkill /T /F 连树强杀。
4. **启动协议**：结算屏开着时启动 bot 会被正确识别为"对局已结束"而退出——属设计行为；正确顺序=先回设置页/战场再启动 bot。

**第 13-17 局结果**：多次因上述工程问题夭折于等待期；**第 17 局（32 分钟，历史最长）**完整验证了快响应体系（10 次 ALARM 反击全部在 1 tick 内），败因=矿车补员规则抢占了坦克资金线（全 0 坦克，38 动员兵/军犬防御战）。已修：矿车第 3 辆起门槛提高到 2800 金、兵营上限补齐到执行闸门。

## 六点十、架构升级：接入官方 Jev 玩家体系（2026-09-21 傍晚）

用户指出官方 API 文档位于 `D:/projects/ra2web.github.io/docs/`（尤其 `player-console-api.md`），
对照学习后完成架构级切换：**弃用自研 Python 主循环，改用官方 werhd-jev-player.mjs + 自建 Python 桥接**。

**官方文档的关键收获（纠错 + 新能力）**
- `werhd.tick()` 存在！之前"不存在"是我写成了 `tick: w.tick`（漏括号，函数被 JSON 吞掉）
- `units('enemy')` = 过滤掉非战斗对象的敌军（官方版比我 owner 前缀过滤更准）
- `werhd.rules(name,type)` 返回对局实际规则（造价/工厂类型/harvester 标记/武器/部署能力）——动态真值，胜过我静态的 UNITS.json
- `weaponVs/inRange(id,id,"current")` 按当前姿态与对空限制判断"能否打到"（zone===1=空中）
- 完整指令面：ForceMove/ForceAttack/Guard/GuardArea/Capture/Occupy/Scatter/EnterTransport/Repair(目标)/超级武器/结盟
- `onTick` 托管回调（单拍 ~8ms 预算）是官方推荐的页内逻辑载体

**官方 werhd-jev-player.mjs 架构（v8.3，官方实测 16:24 获胜纪录）**
```
页内 micro() 每 150ms（零网络）: 集火(按 inRange 最近威胁评分) / 矿车恢复采矿 / 建筑维修(<80%)
                               / 建筑落位 / 部署姿态(GI 架枪) / 镜头导播
页内 decide() 每 600ms: 收集公开状态 -> 生成候选组(construction/vehicles/infantry/
                        deployment/tactics/scouting/defenses/special/investment)
                        -> POST 本机桥接 /decide -> 执行选择(带复查/时限/任务连续性)
```

**自建 Python 桥接（bridge.py，替代官方 tools/werhd-jev-server.mjs）**
- `GET /player.mjs` 等：直接从官方 docs 目录服务模块（含相对 import 链）
- `POST /decide {state, groups}` → TypeSafe `/v1/systemone` 单次批量提问（每组一题）→ `{answers, latencyMs, model}`
- `POST /event` → jsonl 审计日志 + SSE `/events`；`GET /` 官方看板；`GET /status` 统计
- 实测：21 次决策 0 错误，P50 1000ms / P95 1343ms，~1900 tokens/决策（约 $0.0008/决策）

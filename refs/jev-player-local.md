# Jev 本地玩家接入

本示例从正常浏览器进入单机遭遇战。页内脚本仅通过 `window.werhd` 观察和操作玩家；本机 Node 代理持有 TypeSafe key，发送 `state + questions` 到 `/v1/systemone`。Jev 选择候选动作，脚本复查后执行。不会向浏览器提供模型 key。

车辆链路曾在资金充裕时 107 次连续 wait，主要原因是生产问题只强调眼前威胁与储蓄，没有和进攻门槛相配套的集结目标。v8.2 后实战中 22 次满足生产条件的车辆决策全部选择生产；空军改善仅有同快照模型探针证据。看板的“条件检查”来自用户侧逻辑，不是模型思维链。防御、运输等没有合适任务的 wait 仍是合法结果。

API 验收包括失效单位查询、地图尺寸副本、真实引擎 1800 tick / 68373 次查询的 AI 对照，以及驻扎、载员、变卖等动作效果。下面的启动命令、`docs/examples/`、`tools/` 和本地日志路径均相对于 **ra2web-werhd 源工程**；静态发布站点提供游戏、公开 API 类型、文档及其示例源码，不运行 Node 代理，也不携带 key。

## 启动

在仓库根目录创建已被 Git 忽略的 `.env.local`：

```dotenv
JEV_API_KEY=填写你自己的key
JEV_BASE_URL=https://api.typesafe.ai/v1
JEV_MODEL=jev-latest
```

分别运行：

```sh
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
node --env-file=.env.local tools/werhd-jev-server.mjs
```

本地游戏资源沿用开发服的 `/v2/` 代理。没有资源服务时，可以只读方式服务现有缓存：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory ../ra2web-proxy/_cacheRaw/res.site
```

打开 `http://127.0.0.1:5173/`，选择 CDN 资源、单机模式、遭遇战。首轮验证使用普通双人陆地地图、美国阵营、10000 初始资金、0 初始部队、简单 AI。

进局后在同一个页面的控制台执行：

```js
const { attachJevPlayer } = await import('http://127.0.0.1:5174/player.mjs')
window.werhdJev = await attachJevPlayer(window.werhd)
```

重复挂载前先停止旧实例。查看进度与停止：

```js
werhdJev.status
werhdJev.stop()
```

新版默认启用用户侧自动摄像机：优先观察可见交战，其次观察新建筑、部队任务和基地，每次切换至少停留 5 秒。摄像机不会改变部队选择或战斗命令。

```js
werhdJev.setAutoCamera(false) // 保持当前镜头，允许手动观察
werhd.camera.centerAt(60, 45) // 地图坐标，不需要移动鼠标
werhdJev.setAutoCamera(true) // 恢复自动导播
// 也可在 attachJevPlayer(werhd, { autoCamera: false }) 时禁用
```

默认每次托管最多 600 次决策；本机代理最多接受 1500 次请求（可通过 `JEV_MAX_CALLS` 调整）。请求完成后间隔 0.6 秒再观察；独立执行器每 150ms 维护采矿、维修、近距离集火、建筑落地和战况上报，不在 `onTick` 中等待网络。读数跨越超过 180 个模拟 tick 会丢弃。页面离局、玩家战败、手动停止或达到预算时停止托管。

## 实时看板

打开 `http://127.0.0.1:5174/`。看板通过 SSE 自动更新真实模型版本、候选选择与概率、置信度、请求耗时、P50/P95、Token 用量、当前战况和执行时间线。点击历史行可暂停跟随并检查当时结果，点击“返回实时跟随”恢复。看板只接收本机代理的战况和模型结果，不接收 API key。

执行时间线区分模型选择和执行器动作。模型决定宏观任务及 GI 等单位的展开/收起，执行器负责可见射程内集火、补发移动、建筑摆放及采矿维修；不把这些机械动作伪装成额外模型决策。战况与决策延迟分开显示，概率不是胜率。

## 职责与限制

- 模型分别选择基地建设、车辆、步兵、单位展开/收起、侦察和战术任务；各问题同一次请求评估。候选生成按当前可生产项目、经济目标、可见威胁和兵力约束。只有严重受损且基地安全时提供紧急撤退；兵力不足时可选择回基地集结。部署候选基于公开的实际姿态、可见敌人距离及部署前后武器；执行前再次复查，已达到目标姿态时不重复切换。
- 建筑落点由 `canPlace` 搜索，模型选定建筑后的放置由执行器完成。具体单位 id、坐标和费用由代码提供，模型仅返回候选项标识。
- 单位角色、武器和价格从公开 `werhd.rules(name, type)` 读取当前有效规则，包含地图 / MOD 覆盖；代理不读取仓库的静态 INI。分类、武器比较、科技选择和空间搜索均在用户脚本内完成。具体 MOD 的策略效果仍需分别验证。
- 已加入空军、海军、载员/卸载、围墙/武器防御、变卖、驻扎/撤出、修桥/断桥候选。驻扎/载员先等待收起姿态，再提交进入命令，以容器中实际出现的单位 ID 确认成功。跨地形实战仍在验收，候选覆盖不等于各特殊动作均已执行成功。侦察记忆只保存曾经看到的位置。
- `accepted` 只表示本地校验后已调用玩家 API，不能证明模拟已执行。通过后续 `observation` 的单位、队列、电力、资金变化和浏览器画面验证实际效果。
- 不确定性记录在 `confidence` 与 `probabilities` 中；不是实际战斗胜率。原型暂未对置信度设置经过标定的行动阈值。

## 2026-09-20 本地实测

调试地址 `http://127.0.0.1:5173/`，真实模型 `jev-1.13.0`，地图「正式锦标赛地图 A (2)」，10000 初始资金、0 初始部队、速度 6，对手「AI-简单海陆」。从普通菜单进入并通过公开玩家 API 托管，没有读取隐藏敌方状态。

| 对局 | 结算结果 | 界面游戏时间 | 我方摧毁 / 损失 / 建造 |
| --- | --- | --- | --- |
| 第一局 | 失败 | 00:17:35 | 2 / 40 / 27 |
| 第二局 | 失败 | 00:21:16 | 4 / 33 / 23 |

两局均包含迭代：第一局中途调整生产问题与侦察指标；第二局从更新后的生产策略开始，在 tick 15477 修复侦察候选耗尽。开局起点、模型概率和策略并未做严格控制，因此不能把结算差异视为胜率提升证据。

确认完成了基地展开、电厂/矿场/兵营/战车工厂的生产与落地、采矿、步兵/坦克生产、侦察移动、可见敌方攻击和战败自动停止。第二局实际同时拥有过 9 辆灰熊坦克、9 名 GI，均由后续游戏观察确认。

289 次实战推理请求全部成功（另有 1 次接入探针不计入实战汇总）；中位响应 398ms，P95 894ms，最大 1367ms。实战输入 672835 tokens，输出 35615 tokens。记录到 118 次通过本地检查的玩家 API 调用、10 次建筑放置调用、18 次执行前拒绝和 0 次超出时效阈值的模型回答。结果以随后观察和结算验证，不把 API 调用本身当成动作完成。

目标失效、单位消失、队列/资金变化、战败、未知动作、停止后的迟到回答、过期快照、侦察候选耗尽等回归检查通过；已有三组玩家 API / 示例检查也通过，`git diff --check` 通过。

前两局使用的早期策略未能战胜简单 AI。第一局长期偏重经济且装甲成型晚；第二局更早形成装甲，但经济冗余不足，矿场/矿车损失后缺乏恢复手段，战术还会频繁选择等待。后续应分别评估经济补充、威胁响应、目标选择和侦察路径，而不是只继续调整一个宽泛的决策问题。

完整记录：`artifacts/jev-local/summary.json`、`battle-1-result.json`、`battle-2-result.json` 和三个 `session-*.jsonl`。以上为早期验证记录；最新结果见下。
